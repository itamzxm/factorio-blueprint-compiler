# 蓝图格式与坑（Factorio 2.1.24 实测）

> 本文只写**实测过**的东西。每条都注明怎么验的；没验的集中放最后一节，别当结论用。
> 实测环境：Factorio 2.1.24 + base/space-age/quality/elevated-rails/recycler，无第三方 mod。
>
> **关于文中提到的「样本」**：指 27 张公开分享的原版蓝图样本，用来做频次统计和误报校验。
> 它们受来源站授权限制，**不随本仓库发布**；文中的次数与比例是当时的实测记录，
> 想复现得自备样本（放 `data/corpus/`，见 README「样本蓝图」）。

## 一、编码层

    <1 字节版本字符> + base64( zlib( UTF-8 JSON ) )

- 版本字符实测全是 `"0"`，2.0/2.1 也一样。**别把它当世代判据**——世代要看 JSON 里的 `version` 字段。
- 解出来顶层可能是 `{"blueprint": …}`、`{"blueprint_book": …}`、`{"deconstruction_planner": …}`。
- `blueprint_book.blueprints[]` 每项是 `{"index": n, "blueprint": {…}}`；书可以嵌套。
- **`blueprint` 里的 `blueprints` 是另一回事**（2.0 的内嵌蓝图），自带独立坐标系，摊平分析时必须递归，
  否则坐标全串。本轮 27 张样本里 `blueprints` 出现 0 次，属未实测。

## 二、`blueprint.version` 是打包整数

    version == (major << 48) | (minor << 32) | (patch << 16) | dev

实测样本：`562954249961473` → **2.1.24.1**（与本机版本一致）；`562949957025792` → 2.0.55.0；
`562954250027018` → 2.1.25.10（作者版本比本机高）。**读进来先解这个，再决定要不要怪字段缺失。**

## 五、坐标与方向（最容易错的一块）

### 5.1 位置是实体中心，单位是格

- 奇数格实体落在 **.5 坐标**（`transport-belt` 在 (5.5, 3.5)），偶数格实体落在**整数坐标**（`stone-furnace` 在 (4, 0)）。
- 实体占据的格心 = `floor(x - w/2) … floor(x - w/2) + w - 1`（y 同理）。
  **别写成 `round(x-0.5)`**——3 格宽的实体落在 3.5 时那样算会整体右移一格。本轮踩过。
- 转 90° 后宽高互换：方向 4/12（东/西）的有效尺寸是 `(h, w)`。

### 5.2 `direction` 是 0/4/8/12 的循环

0=北(−y)、4=东(+x)、8=南(+y)、12=西(−x)。**是 16 分度枚举，普通实体的合法值是 4 的倍数**，
轨道类会出现 0–15 全量（见第六节）。旋转公式（屏幕坐标，y 向下）：

    rot(x, y, 0)  = ( x,  y)
    rot(x, y, 4)  = (-y,  x)
    rot(x, y, 8)  = (-x, -y)
    rot(x, y, 12) = ( y, -x)

原型里的 `pickup_position` / `vector_to_place_result` / `pipe_connections[].position` 都是
**朝北坐标系**下的相对坐标，套上面的函数就是任意朝向的实际偏移。

### 5.3 ⚠ 物流臂的 `direction` 指向「取货侧」，不是「放货侧」

本轮花掉最多时间才钉死的一条。证据：样本 `-P6fxvwb5tPSLLD3e1Kf`（石炉阵列）的排布是
`带 i 炉 炉 i 带`，其中 `dir=12` 的 inserter 取货落在西侧的带上、放货落在东侧的炉上：

    inserter at (-3.5,-8.5) dir=12 | pickup->['transport-belt'] | insert->['stone-furnace']

原型数据同口径：`inserter` 的 `pickup_position=[0,-1]`、`insert_position=[0,1.2]`，朝北时取北、放南。
**下游写「臂朝向机器」的代码要反过来想。**

注意 `mining-drill` 的 `vector_to_place_result=[0,-1.85]` 是**朝北就往北出矿**——方向指向产出侧，
跟臂的口径不同，别套同一个直觉。这两条都在样本上验过（钻头 32/32 命中、臂见上例）。

### 5.4 ⚠ 有些机器根本不认 direction，而且**认不认还要看有没有写 recipe**

这条比"能不能转"更要命，因为它是**静默**的——不报错，方向就是不生效。

1. **能不能转，只能信真机**（`dirs` 字段）。装配机 1/2/3、石/钢/电炉、电磁厂、生化室
   在蓝图里写任何 direction，游戏建出来读回恒为 0。真实蓝图里确实有人给装配机写 direction，
   游戏照收、不报错、也不理——**校验器不许因此报错，最多 warning**（`direction_ignored_by_game`）。
2. **有些机器认 direction，但要求蓝图里同时写了 `recipe` 才生效——这是逐实体的，不是按类型推的。**
   实测裸建矩阵（同表面、同机器、唯一变量是 recipe）：
   - `foundry`：裸建 `direction=8` → 读回 **0**；写 `recipe=casting-iron` → 读回 **8**；
     写非流体配方 `recipe=transport-belt` → 又回 **0**。`cryogenic-plant` 同根因。
     → 真值表标 `direction_requires_recipe: true`（目前只有这两个）。
   - `recycler` / `chemical-plant` / `oil-refinery`：**裸建也认**，别误伤。
   - `electromagnetic-plant` / `biochamber`：探针**带了配方**仍只读回 1 档——它们就是不可旋转，
     跟配方无关。**判据是"带配方时能不能读到 >1 档"，不是"有没有 crafting_categories"，也不是方不方**：
     `chemical-plant` 方形但裸建也认，`cryogenic-plant` 方形但裸建就丢。
   **对编译器的要求**：给 `dirs > 1` 的机器写方向时一律把 `recipe` 一起写上——对配方门控的那批是必需的，
   对其余那批无害（真蓝图里 70 个"方向非零的带配方机器"有 60 个本来就带着 recipe）。

真机方向的判据是「把 direction 写进单块蓝图 → 建出来 → 读回」，不是 `create_entity` 时给参数——
后者对这几类原型一律返回 0，会把"能转"误判成"不能转"，`foundry` 就是被这样误判过一轮。

### 5.5 各 type 在样本里实际用到的方向

| type | 实测 direction |
|---|---|
| transport-belt / inserter / underground-belt / pipe-to-ground / boiler | 0,4,8,12 |
| pipe / heat-pipe | 只用 0（四面全通，方向无意义） |
| furnace | 0, 8（本轮样本只出现两种） |
| generator（蒸汽机 / 汽轮机） | 0, 4, 12 |
| electric-pole | 0,4,8,12（纯外观，落地朝向无功能意义） |

### 5.5 ⚠ 连接关系必须写进蓝图，不许用距离推

三次同类失败，形状一模一样——**几何算得出、字段里没写**：

| 次 | 现象 | 根因 |
|---|---|---|
| ① | foundry 转了向，游戏读回 0 | 没写 `recipe`，方向被忽略 |
| ② | 地下管接反 | 口径推错（管口朝 direction，地下段朝 direction+8） |
| ③ | **12 根电塔 = 12 张独立电网** | 蓝图里没写 `wires`，一根铜线都没有 |

第③条实测：24 台石炉阵列，12 根中电塔。`--powered`（每塔各接一台发电机、只测覆盖）→ 72 个臂全部有电，
覆盖没问题；`--powered-single`（只接第一根塔，模拟玩家实际只拉一条线）→ **58/72 个臂 no_power**。
补上 21 条 `[A,5,B,5]` 之后，`--powered-single` → **0 个 no_power**。

**规矩**：凡连接关系（电网、电路、管线、带子上下游），一律以蓝图里**实际写下的字段**为准。
距离近不等于连着。`bpcompile/primitives.py` 的 `connect_poles()` 就是这条规矩的落地。


### 5.6 ⚠ 两个「几何全对、lint 干净、就是不产出」的坑

第四、五次同类失败，形状比 5.5 更隐蔽：**字段都写对了，但物理上运不动。**
游戏不报错、lint 不报错，只有 `by_product` 会露馅。

| 次 | 现象 | 根因 |
|---|---|---|
| ④ | 绿板机永远缺料，铜线机 `full_output` | 铜线带**往东流**，落在东侧的铜线回不到上游取料格 |
| ⑤ | 铁板进不来，绿板 0 个 | 两条输入带只隔 1 行，**两个端口放在同一处**，夹具互相抢格子 |

**第④条**：铜线机排在东侧，取料格在西侧。带子往东流 = 货只会越走越远。
改成往西流（`direction=12`）之后所有铜线都要经过所有取料格；产出从 0 变成 26 个
——而这一步之前，蓝图是**完全合法**的。

**第⑤条**：`bp_testbench` 给每个输入端口建一排夹具（带 + 臂 + 箱子），横向要 4~5 格。
两个端口如果在同一列上（这里只隔 1 行），后一个夹具会挤掉前一个，
表现为**某个输入一个都没进来**。所以模板里让铁板带往西多伸 5 格，把两个端口横向分开。

### 5.7 ⚠ 同一条判据不能有两个实现路径

**凡是液口 / 端口类几何，一律走 `machine_fluid_ports` / `connect_machine_port`，不许手摆坐标。**

不是风格问题：现有实现里已经把落点算好了（"液口在机器边格上，管子要接在**再往外一格**"），
手摆一遍就等于绕过这条判据。塑料模板就是这么错的——5.5 写了、函数也实现了，但模板里手工摆管子，
于是照踩。

这轮还暴露了第二个同源错误：`underground_pipe_pair(start, flow, span)` 的跨度是**从起点往 flow 方向量**，
把"出口格"当起点传进去，隧道就会一路钻到机器底下去。真机读数：

    chemical-plant fluid_boxes = [{index:1, neighbours:1, expected_connections:2, segment: nil}]

`segment = nil` 就是"机器压根没接进管网"。**这是查流体问题最快的判据，比看产量早一步**：
先看 `segment`，nil 是没接上，非 nil 而产量 0 才是配方/容量/供电问题。

**规矩**：

0. **液口几何只走函数，不手摆**；调地下管时想清楚"起点还是终点"；
1. **排带子之前先想货从哪来到哪去** —— 方向错了，几何再对也是死路；
2. **想清楚谁能搬得动** —— 长臂 0.83 个/秒、快臂 2.31 个/秒，`machine_pair` 会当场核算；
3. **多个输入端口之间要留够夹具的地盘**（横向 5 格以上）。

判据一律看 `by_product`（按机器配方分组），不看 `produced`（它把中间品也加进去）。

## 六、轨道类不要按普通实体处理

- `rail-signal` / `rail-chain-signal` 的 direction 是 **0–15 全 16 档**（奇数值也在用；本轮样本实际
  出现过 12 个值，探针在真机上 16 档全部读回）。
- `curved-rail-a/b`、`half-diagonal-rail` 只用偶数 0–14，且**位置奇偶跟普通实体规则不符**
  （`curved-rail-b` 是 2x5 却落在整数 y 上）。
- `rail-support` 实测 0–15 全用；`rail-ramp` 是 4x16 的怪尺寸。
- `data/prototypes.json` 里轨道类的 `dirs` **只认真机探针**（样本里那点取值推不出档数），
  `dirs_source: "probe"`；测不到的记 `null` + `dirs_source: "rail"`，**不是 0**，别当"不可旋转"用。
- 样本里还有 `elevated-straight-rail` / `rail_layer: "elevated"`，同一格上下两层轨道。

## 七、尺寸真值表怎么来的，可信到什么程度

`data/prototypes.json` 的 `w`/`h` 默认 = `ceil(collision_box)`。然后拿样本做了**位置奇偶校验**：
偶数格实体必须落整数坐标、奇数格必须落 .5，转到东/西时宽高互换。27 张样本、76 个出现过且非轨道的
实体名 → **76/76 吻合**（校验账在 `special.corpus_parity`）。

只有两条硬改过（`size_source: "override"`，理由在 `size_note`）：

- `train-stop` coll 1x1（只是中间立柱），实为 **2x2**。
- `offshore-pump` coll 1.2x1.35 取整得 2x2，但 9 个样本全落在半整数坐标 → **1x1**。

这两条正是"别信推导、拿真实数据对"的例子。

## 八、quality 的两个坑

1. **`quality` 与 `recipe_quality` 是两个字段**：前者是实体本体品质（样本 28 个，全 `legendary`），
   后者是**配方**品质（170 个，全 `normal`）。只读 `quality` 会漏掉配方品质。
2. 品质枚举实测 6 个：`quality-unknown` / `normal` / `uncommon` / `rare` / `epic` / `legendary`。
   缺省即 normal——**不写等于 normal，不是"无品质"**。

## 九、其它已经踩过的坑

- **`recipe.energy_required` 缺省 = 0.5 秒**，不是 0 也不是 1。662 个配方里 63 个没写
  （`iron-gear-wheel`、`copper-cable` 都是）。真值表用 `time_default: true` 标出来。
- **`recipe.categories` 缺省 = `["crafting"]`**，不是空。写了这个字段的只有 509/662。
- **2.0 改了 `request_filters` 结构**：扁平数组 → `{"sections":[{"filters":[…]}]}`。
  拿 1.1 时代的解析器读 2.1 蓝图会**静默读到空请求**。
- **`wires` 的连接点编号是整数**：`5/6` = 铜线（电力），`1/2` = 红/绿信号线，`3/4` = 另一个信号口。
  样本里 340 条塔对塔的连线**全部是 `5`**（draftsman 的 `collection.py` 也是用 `{5, 6}` 过滤铜线）。
  这条以前写错过一次（把 `5` 当成绿线），照错的写会让电网整块失效。
- `blueprint.tiles` 的坐标是整数格，跟实体位置的 .5 规则不同，别混。
- `mirror: true` 是 2.0 才有的翻转标记，翻转后取货侧会跟着镜像——**镜像逻辑本轮未验证**。
- 回收配方的 `results` 里会出现 **amount 为 0** 的条目（`tungsten-carbide: 0`），是期望值不是错数据，别当解析失败。

## 十、还没验的（别当结论用）

1. **「几档朝向」和「蓝图里写没写 direction」是两件事，别用一个数糊住**（结论见 5.4）。原型数据里没有这个字段
   （`EntityPrototype` 属性表查过，全量 dump 里也没有），是 C++ 按 type 定的。真值表因此给了三个：
   - `dirs` = **游戏认几档**，只认真机蓝图往返读数（`data/direction-probe.json`，`tools/probe_directions.py`）。
   - `observed_dirs` = **真实蓝图里玩家写过哪些方向**。这是"玩家干了什么"，不是"游戏认什么"。
   - `direction_accept` = **校验器必须放行的取值**。非轨道实体给 `[0,4,8,12]`。

   三者在装配机/炉子上会打架，**打架时探针是对的**：游戏解析蓝图时就把这些原型的 `direction` 丢了，
   写 `direction=12` 不报错也不生效。样本侧的旁证是**字段本身在不在**：
   `electric-furnace` 177 个全部没有该字段、`assembling-machine-1` 30 个全部没有、`assembling-machine-3` 55 个里 49 个没有；
   而 `oil-refinery` 14 个**全部有**、`chemical-plant` 53 个里 37 个有。**能转的才带字段。**
   - 所以校验器**不许**因为"AM3 上写了 direction=12"报错——真实蓝图里有（样本 4 例），游戏照收。
     该报也最多是 warning。
   - 全账在 `special.dir_probe_conflicts`（现 4 条：`assembling-machine-3` 与三种电线杆）。
   - 已排除的反例：`two_direction_only` 不是朝向数，它指"贴图只有 2 套"；蒸汽机带这个标志，实测 2 档。
2. 除 `foundry` / `cryogenic-plant` 外，还有没有别的"配方门控"机器**没测过**。
   目前只在 10 台机器上跑过裸建矩阵，其余 `dirs > 1` 的机器是否也依赖 recipe 未知——
   所以真值表只对测过的两个标了 `direction_requires_recipe`，**其他一律不标，不是标 false**。
3. `offshore-pump` 是 1x1 还是 1x3——只有奇偶证据，没有绝对尺寸证据。探针只测方向，不解这条。
4. 内嵌蓝图（`blueprint.blueprints`）的坐标原点规则。
5. 红线 / 铜线的 `wires` 线种编号。
6. `mirror` 翻转后的端口映射。
