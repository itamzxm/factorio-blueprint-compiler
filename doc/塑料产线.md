# 塑料产线 plastic_line

> ✅ **能跑了，只差 6 个到验收线。** `target_rate=4` 那版 48 实体，60 秒 **114 塑料** / 理论 120 = 95%；
> 默认 `target_rate=2` 是 26 实体、58 / 60 = 97%。化工厂全部 working，气路通。

## 结构

化工厂（3x3）一排，液口在北侧两个格（朝北，进料）和南侧两个格（朝南，出料）。

    py-4  气主管 ────────────────  端口 (-1, py-4)
    py-3  地下管起点（朝北接主管）
    py-2  煤带 ──────────────────  端口 (-1, py-2)
    py-1  地下管出口（地面口朝机器）；煤臂在中间格
    py..py+2  化工厂
    py+3  取塑料的臂
    py+4  塑料带 ────────────────  端口在东端

气走**地下管跨越煤带**（跨度 2）。**落点全部由 `machine_fluid_ports` 推导，模板里没有一处手写坐标。**

## 一个查流体问题的快判据

「气通没通」第一判据是**机器里有没有液体**：

    两台化工厂 get_fluid_contents() = {petroleum-gas: 80} / {petroleum-gas: 80}

空 = 没接上；有液体但产量是 0 = 接上了，问题在配方 / 容量 / 供电。

⚠ **不要用 `fluid_box.segment` 判机器。** 它对管道可靠、对机器不可靠：这条线的两座化工厂
`get_fluid_segment_id(1)` 读到 nil，但它们各自有 80 单位石油气，也都产出了塑料。

这里踩过的坑：`underground_pipe_pair(start, flow, span)` 的跨度是**从起点往 flow 方向量**，
把「出口格」当起点传进去，隧道就一路钻到机器底下——游戏不报错、气就是不通。现在落点由
`machine_fluid_ports` 推导，这条已经修掉。

## 从 18 到 114：坏的不是模板，是夹具

早先这条线 60 秒只出 18 个塑料，读数是「煤没到炉子」——煤线终点落在 4 个收货钢箱里，
进料带是空的。根因不在几何：**夹具在猜哪条带是输入**，把内部煤带当成成品线收走了。

夹具改成**声明驱动**（被测方声明每个外部供给点：格 + 物品 + 是不是流体，供给方只照做、
没声明一格都不灌）之后，同一张图从 18 个变成 114 个。
形状一样的还有绿板那次「把铜线带当输出口」——**同一个错，换了一条线又出现一次。**

## 已排除

- 「地下管不能从带子底下穿」——游戏认这个用法。
- 「液口在四角」——化工厂的接口位置由 `machine_fluid_ports` 推导，落点不再手摆。

## 为它新增的能力

`bp_testbench` 现在认**流体端口**：端口里的物品是 fluid 时走 `infinity-pipe` 直灌，不走带子。
没有这条，塑料连自测版都生成不出来。
